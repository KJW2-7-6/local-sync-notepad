# 실제 Windows PC 두 대에서 확인하기

이 절차는 클라우드의 같은 컴퓨터 안에서 실행한 검사로 대신할 수 없는 항목을 확인하기 위한 것입니다. 결과를 직접 적을 수 있도록 만들었습니다.

## 준비

1. Windows 10/11 x64 PC 두 대에 같은 설치 파일을 설치합니다. 메인 PC는 공유기의 랜선, 노트북은 그 공유기의 일반 Wi-Fi를 사용합니다.
2. 각 PC에서 앱을 켭니다. 기기 관리에서 `DESKTOP-MAIN`, `LAPTOP-TEST`로 이름을 정합니다.
3. Windows 설정의 네트워크 유형을 ‘개인’으로 정합니다. 공유기 인터넷 케이블을 뽑아도 공유기 전원과 LAN은 유지합니다.
4. 검사할 때 비밀번호·개인 문서 대신 아래의 예제 텍스트를 사용합니다.

| 저장                   | 두 앱 모두 정상 종료 후 실행              | 메모·방·신뢰 기기 복원                         |                |

## 클립보드

1. 두 PC에서 자동 공유 OFF를 유지합니다. 한 PC에서 ‘직접 보내기’로 `https://example.com`을 보냅니다. 상대 기록에는 나오지만 OS 클립보드는 바뀌지 않아야 합니다.
2. 양쪽 자동 공유를 ON으로 바꿉니다. 메인 PC의 브라우저나 다른 앱에서 `PC1-복사-001`을 복사하고 노트북의 다른 앱에 붙여넣습니다.
3. 노트북에서 `PC2-복사-002`를 복사하고 메인 PC에 붙여넣습니다.
4. 30초 기다립니다. 기록 수가 끝없이 늘거나 클립보드가 계속 바뀌면 실패입니다. 각 복사 1건만 기록되어야 합니다.
5. 항목을 다시 복사하고 고정합니다. 다시 복사는 다른 PC에 새 항목을 만들지 않아야 합니다.
6. 한 PC에서 항목/전체 삭제합니다. 그 PC의 기록만 지워지고 다른 PC 기록은 유지되어야 합니다.
7. 앱을 닫고 켜서 고정 기록이 남는지 확인합니다. 마지막으로 자동 공유를 OFF로 돌립니다.

클라우드 화면 검사는 두 앱이 하나의 OS 클립보드를 같이 사용하는 환경입니다. 위의 독립 Windows 클립보드 전달은 실제 두 PC에서 추가 확인해야 합니다.

## 방화벽 또는 연결 실패 해결

1. 두 PC가 같은 공유기에 있고, 게스트 네트워크나 기기 격리가 아닌지 확인합니다.
2. 방장 설정에 나온 현재 `IP:포트`를 사용합니다. 공유기가 IP를 바꾸거나 포트가 이미 사용 중이면 이전 주소는 틀릴 수 있습니다.
3. Windows 보안 → 방화벽 및 네트워크 보호 → 방화벽에서 앱 허용에서 **Local Sync Notepad의 개인 네트워크** 접근을 확인합니다. 공용 인터넷 접근이나 전체 방화벽 해제는 필요하지 않습니다.
4. PowerShell에서 `Test-NetConnection 192.168.0.10 -Port 48765`를 실행합니다. 숫자는 방장 화면의 실제 주소와 포트로 바꿉니다. `TcpTestSucceeded: True`면 TCP 연결은 도달합니다. False면 방장 실행·주소·방화벽·공유기 격리를 점검합니다.
5. TCP는 성공하지만 자동 검색만 안 되면 UDP 5353 규칙을 확인하고, 일단 수동 연결을 사용합니다.
6. 회사 PC 정책으로 허용할 수 없으면 관리자에게 개인 LAN의 해당 TCP 포트와 UDP 5353만 요청합니다. 관리자 권한이 필요한 변경은 사용자가 직접 승인해야 합니다.

검사할 때 인터넷 연결을 끊었다면 마지막에 복구하세요. 앱은 인터넷 포트 포워딩이나 방화벽 전체 해제를 요구하지 않습니다.
