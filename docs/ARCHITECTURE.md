# 구조와 보안 설명

## 프로그램 구성

- `src/electron`: Windows 창·시스템 클립보드·Windows 자동 실행·파일 내보내기·OS 보호 저장을 담당한다.
- `src/core`: LAN 연결·승인·기기 인증·공동 문서·기록·저장. 화면과 독립되어 같은 코드를 여러 인스턴스로 검사한다.
- `src/renderer`: React 화면과 CodeMirror 편집기. 파일 시스템이나 네트워크에 직접 접근하지 않는다.
- `src/shared`: 화면이 사용할 수 있는 요청과 공개 상태의 형식을 정의한다.
- `tests`: 실제 TLS 소켓과 독립 데이터 폴더, 실제 mDNS, 실제 데스크톱 창을 사용한 검사.

창은 Electron의 분리 실행과 제한된 통신 통로를 사용한다. 일반 실행에서는 화면 격리 기능이 켜져 있다. Linux 자동 검사의 `--no-sandbox`는 컨테이너가 Chrome의 격리 도구를 설치할 수 없는 경우에만 검사 명령에서 사용한다. 배포 앱의 기본 옵션으로 추가하지 않는다.

## 방과 연결

처음 방을 만든 PC가 계속 방장이다. 방장은 TCP 48765를 우선 사용하고, 사용 중이면 운영체제가 빈 포트를 선택한다. 설정 화면에서 실제 포트를 확인한다. mDNS(UDP 5353)가 이름·방 번호·연결 주소·공개 인증서 확인값을 알려준다. 검색은 편의를 위한 정보이고, 참가 승인과 기기 인증을 대신하지 않는다.

방 번호는 혼동하기 쉬운 문자를 줄인 무작위 6자리다. 비밀 비밀번호가 아니며 LAN 검색에 공개된다. 방 번호만으로 내용을 읽을 수 없다. 수동 연결은 사설 IPv4 `주소:포트`로 제한한다. IPv6 전용 네트워크는 지원하지 않는다.

QR에는 `localsync://join?code=...&address=...&fingerprint=...&room=...`가 담긴다. 첫 화면에서 QR 이미지를 읽거나 참가 링크를 붙여넣어 사용할 수 있다. 이 버전은 Windows URL 연결 프로그램 등록이나 카메라 사용을 요구하지 않는다.

## 첫 참가와 이후 신뢰

1. 각 설치의 첫 실행에서 무작위 기기 ID와 Ed25519 인증 키를 생성한다. 하드웨어 시리얼이나 계정 로그인을 사용하지 않는다.
2. 방장은 스스로 생성한 TLS 인증서로 암호화 연결을 연다. 처음 참가할 때 QR 또는 검색의 인증서 확인값을 확인한다. 수동 연결의 첫 접속은 상대 인증서를 최초 신뢰하는 방식이다.
3. 연결마다 새 무작위 질문을 보내고, 참가 기기가 비밀키로 서명해서 해당 키를 소유했음을 증명한다. 질문과 방 ID를 서명에 포함하여 다른 연결의 서명을 재사용하지 못하게 한다.
4. 방장과 참가 화면에 기기 키·연결 질문·서버 인증서를 포함해 계산한 동일한 6자리 확인 번호를 표시한다. 첫 접속은 두 화면의 번호와 기기 이름을 비교한 뒤 승인한다. 비교 없이 낯선 요청을 승인하면 보안 보장이 약해진다.
5. 승인된 기기의 공개키만 신뢰 목록에 보관한다. 다음 접속은 기기 ID와 실제 키의 소유를 모두 확인한다. 승인 전에는 메모·클립보드·기기 목록을 제공하지 않는다.
6. 참가 PC는 방장 인증서를 저장하고 이후 접속에서 동일한지 확인한다. 바뀌면 자동으로 다시 신뢰하지 않고 연결을 차단한다.

WebSocket 클라이언트는 운영체제의 일반 웹사이트 인증서 검사 대신, 연결 직후 실제 서버 인증서의 SHA-256 값을 직접 비교한다. 자체 인증서를 사용하는 오프라인 LAN 앱이라서 이 방식을 사용한다. 인증서가 맞는 것을 확인하기 전에 기기 서명이나 문서를 보내지 않는다.

## 공동 메모와 끊김

Yjs의 공동 문서에 CodeMirror를 연결한다. 입력한 변경은 앱 내부 통신 → 승인된 TLS 소켓 → 상대 편집기로 즉시 전달된다. 일정 시간마다 전체 문서를 새로 받아오는 방식은 사용하지 않는다. 처음 접속 및 재접속 시에만 문서 상태를 교환해서 미전송 변경을 합친다.

같은 위치의 동시 삽입도 일정한 순서로 합쳐진다. 사용자가 의도한 문장의 의미까지 자동으로 판단하지는 않는다. 방장이 꺼져도 기존 참가 PC의 메모는 편집·저장하고 다시 연결하면 합친다. 자동 방장 교체나 인터넷 중계는 제공하지 않는다.

방이 바뀔 때 문서 번호를 바꾼다. 이전 편집 화면에서 늦게 도착한 변경은 새 방에 적용하지 않는다. 메모는 UTF-8 2MB까지, 전달 프레임과 저장한 공동 문서 상태는 4MB까지다. 아주 많은 삭제·교체로 내부 편집 이력이 커지면 텍스트가 작아도 제한에 도달할 수 있다. 이 경우 텍스트를 내보낸 뒤 새 방을 만들 수 있다.

## 클립보드

OS의 텍스트 클립보드를 250ms마다 읽는다. 기본값 OFF이고 방이 연결된 동안만 자동 전송한다. 각 항목에 무작위 변경 ID와 인증된 원본 기기 정보를 붙인다. 받은 항목을 시스템 클립보드에 쓰면서 내용 확인값도 갱신해 다시 전송하지 않는다. 이미 본 변경 ID도 무시한다. ‘다시 복사’는 해당 PC에서만 복사한다.

자동 공유 OFF일 때 수신된 항목은 기록에서 볼 수 있지만 시스템 클립보드를 덮어쓰지 않는다. OFF 동안 복사한 내용은 ON으로 바꾸었다는 이유만으로 전송하지 않는다. 끊긴 동안의 새 클립보드는 자동으로 재전송하거나 다른 PC 기록과 합치지 않는다.

텍스트 항목 256KB, 기기당 최근 100개, 고정 최대 30개다. 고정·삭제·전체 삭제는 기기별 기록 관리다. 이미지와 파일을 넣을 수 있는 별도 메시지 종류를 나중에 추가할 수 있게 메모 전송과 분리했다.

## 데이터 파일

설정·기기 비밀키·인증서 비밀키·방·문서·기록을 `state.bin`에 보관한다. 먼저 임시 파일을 완성하고 디스크 쓰기를 확인한 뒤 기존 파일을 교체한다. 직전 정상 파일은 `state.bin.bak`에 보관한다. 파일 하나가 손상되면 백업을 읽고, 둘 다 읽을 수 없으면 기존 데이터를 덮어쓰지 않고 복구 안내를 표시한다.

Windows 앱은 Electron `safeStorage`를 통해 Windows의 사용자 계정 보호 저장(DPAPI)으로 파일 전체를 암호화한다. 다른 Windows 계정이나 다른 PC로 파일을 복사하면 정상적으로 읽지 못할 수 있다. 테스트용 Node 환경 또는 Linux에서 OS 보관함이 없으면 제한된 권한의 평문 파일을 사용하고 화면에 안내한다. 같은 사용자 권한의 악성 프로그램으로부터 기밀을 완전히 지키는 기능은 아니다.

메모 저장은 변경 후 약 120ms 단위로 묶고, 정상 종료 시 마지막 변경을 저장한다. 전원이 갑자기 끊기면 마지막 약 120ms의 입력은 저장되지 않을 수 있다. 클립보드에서 지운 항목은 직전 백업 파일에 남아 있을 수 있다. 삭제 기능은 보안 삭제가 아니다.

## 신뢰 해제와 한계

기기를 제거하면 현재 연결을 닫고 이후 변경 전송을 차단한다. 다시 접속하려면 새 승인이 필요하다. 이미 상대 PC에 전달한 메모나 클립보드를 원격으로 지우지는 않는다. 방장 PC의 신뢰 목록 또는 인증 비밀키가 공격자에게 탈취되면 신뢰 모델이 손상될 수 있다.

설치 파일은 유료 코드 서명 인증서를 사용하지 않는다. Windows SmartScreen이 알려지지 않은 게시자로 표시할 수 있다. 공식 저장소 다운로드와 체크섬으로 파일을 확인한다. OS 경고를 임의로 끄거나 자동으로 우회하지 않는다.
